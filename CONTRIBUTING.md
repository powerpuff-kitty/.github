# Contributing

Read the target repository's README, installation guide and applicable contributor
or agent instructions before changing files. Describe the concrete problem and
resulting behavior, keep changes scoped, and preserve unrelated work.

For Skills, each root skill folder is self-contained: keep its SKILL.md, license
and referenced resources together. Check metadata, links and any relevant local
helpers. Do not add collection scaffolding solely to match a template.

For Agents, edit canonical profiles, teams, packs or adapters and regenerate
exports using the documented commands. Do not hand-maintain generated copies.
Run the repository's documented validators and tests appropriate to the change.

Pull requests should explain what changes, why it helps, actual validation and
remaining limitations. Distinguish scenario specifications from retained model
executions. Include reproduction steps for a defect and avoid unsupported claims
about host compatibility, security, search rankings or task success.

Keep secrets and private user/customer data out of issues, fixtures and logs.
Use the private security route for suspected vulnerabilities. Discuss changes
that introduce dependencies, licensing or substantial new interfaces before
merging. Contributions retain applicable repository/file license terms.
