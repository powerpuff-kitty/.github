# Security reporting

For a suspected vulnerability, open the affected repository's **Security** tab
and choose **Report a vulnerability** when available. Private vulnerability
reporting is enabled for `powerpuff-kitty/skills` and `powerpuff-kitty/agents`.
This does not imply the setting is enabled for every repository inheriting this file.

Include the affected revision/version, prerequisites, minimal reproduction,
impact and a proposed fix if available. Remove credentials, private files and
unnecessary exploit payloads. Do not disclose vulnerability details in public
issues or test against systems/accounts without authorization.

If the affected repository has no private reporting control, use its documented
private contact. If none exists, open a public issue requesting a private reporting
channel without including vulnerability details. Do not assume an invented email
address or send sensitive findings to an unrelated repository.

The current default-branch source is the maintenance target unless a repository
states a supported release policy. Historical tags are not a guarantee of security
backports. No response-time or vulnerability-free guarantee is implied.
